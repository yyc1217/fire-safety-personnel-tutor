# 間隔重複複習排程規格（複習排程規格）

> 本文件為 `spaced-repetition`（`/複習排程`）與 exam-tutor 記錄排程時的**單一規格來源**。
> 程式實作在 `skills/spaced-repetition/`（`scheduler.py` 演算法、`storage.py` 儲存、`cli.py` 介面）；
> 本檔定義**演算法參數、`item_id` 命名、品質分數對映與資料位置**，程式與 SKILL.md 只引用、不各自定義。

## 定位：排程只回答「什麼時候該再看一次」

| 檔案 | 負責 | 不負責 |
|------|------|--------|
| `progress.json` | 作答紀錄（`attempts`）、弱點次數（`weak_tally`）、內容覆蓋度（`coverage`） | 複習時機 |
| `review_schedule.db` | 每個知識點的記憶強度（`ease_factor`）與下次複習日（`next_review`） | 作答內容、掌握度百分比 |

兩者以 **`item_id`＝既有標籤 key** 對齊，內容不重複存。`/掌握度` 仍只讀 `progress.json`；
`/弱點複習` 依「錯幾次」選題，`/複習排程` 依「該不該再看了」選題——**兩者互補，不互相取代**：
弱點複習答對就算克服，間隔重複則主張「答對了也會忘，只是可以晚點再問」。

## 資料位置（鐵則）

排程檔為 `<data_dir>/review_schedule.db`（預設 `~/.fire-safety-tutor/review_schedule.db`）。
**絕不寫入 plugin 目錄**——plugin 目錄唯讀（見 [`user-config-spec.md`](user-config-spec.md)「寫入邊界」），
且每次更新 plugin 會覆寫，排程放那裡等於隨時被清空。`data_dir` 依 `user-config-spec.md`
之「設定解析順序」取得後，以 `--data-dir` 傳給 `cli.py`（或設環境變數 `FIRE_SAFETY_DATA_DIR`）。

## `item_id` 命名（跨檔對得上才有意義）

**`item_id` 一律沿用既有標籤維度 key**，與 `corpus/tags_index.json`、`progress.json` 之
`weak_tally`／`coverage` 同一套字串。**不得自創**如 `co2_hold_time_calc` 這種只有排程檔看得懂的 ID
——那樣就無法用 jq 對 `tags_index.json` 反查考古題來出題，也無法和弱點次數、覆蓋度對照。

```
<tag key>              整條／整個設備／整個主題為一個複習單位
<tag key>#<要點名>      細到單一要點（公式、單一數值、單一款目）
```

| 型態 | `item_id` 例 | 說明 |
|------|-------------|------|
| 法條 | `by_article:設置標準第31條` | 條號短名對齊 `tags_index.json`；增訂條文用「第 N 條之 M」（如 `by_article:設置標準第111條之1`） |
| 法條之單一要點 | `by_article:設置標準第82條#藥劑保持時間` | `#` 後沿用 `coverage["by_article:…"].points` 既存要點名，不另起新寫法 |
| 設備 | `by_equipment:滅火器` | 整個設備單元 |
| 系統 | `by_system:化學系統` | 少用；系統層級通常太粗，不利排程 |
| 火災學主題 | `by_topic:燃燒理論` | 主題層級 |
| 火災學知識點 | `by_topic:燃燒理論#火三角與火四面體` | `#` 後沿用 `reference/索引/火災學主題知識點索引.md` 之知識點開頭關鍵語 |
| 延伸知識 | `延伸知識:四種乾粉化學反應式` | 不在法規條文者（見 `索引/設備條文索引.md` 文末清單）；**無對應 tag，反查考古題會落空**，屬預期 |

`#` 前一段必須是可對回 `tags_index.json` 的 key；前綴不在上表者，`cli.py` 會在 stderr 提醒
（**不阻擋**，以免擋住合理的新型考點），看到提醒就回頭確認命名。

**`category` 欄**填科目或系統，取值建議固定為：`火災學`、`消防法規`、`水系統`、`化學系統`、
`警報系統`、`避難系統`、`搶救上必要設備`（與 `by_system` 及各等別科目一致，便於 `--category` 篩選）。

**`citation` 欄**填法規依據，格式與批改時的法源標注一致（法規名＋條／項／款／目，如
`各類場所消防安全設備設置標準 §82 第 1 項第 2 款`）。呈現複習項目時**必附 citation**；
但**條文全文一律當場從 `statutes/` 重新取用**（Grep 定位行號 → Read 帶 offset），
不得拿排程檔裡的 citation 當條文內容——排程檔只存「指到哪一條」，不存法條快照。

## 演算法（SM-2 簡化版）

答題後給 **0–5 品質分數**（0＝完全不會，5＝秒答對）：

| 條件 | `repetitions` | `interval_days` |
|------|---------------|-----------------|
| `quality < 3`（答錯） | 歸零 | 重置為 1 |
| `quality >= 3`，第 1 次答對 | 1 | 1 |
| `quality >= 3`，第 2 次答對 | 2 | 6 |
| `quality >= 3`，第 3 次以後 | ＋1 | `round(前次 interval_days × ease_factor)` |

`ease_factor` **每次答題後**更新（含答錯），初始 2.5，**下限鎖 1.3**：

$$\text{ease} \leftarrow \max\left(1.3,\; \text{ease} + 0.1 - (5 - q)\left(0.08 + (5 - q) \times 0.02\right)\right)$$

各品質分數的增減量：$q=5$ 為 $+0.1$、$q=4$ 為 $0$、$q=3$ 為 $-0.14$、$q=2$ 為 $-0.32$、
$q=1$ 為 $-0.54$、$q=0$ 為 $-0.8$。上限不設限（秒答對就讓間隔自然拉長）。

`next_review = last_reviewed + interval_days`（一律西元 ISO 日期）。

**兩個已固定的實作細節**（原始 SM-2 描述留有空間，固定下來以免行為漂移，並有測試把關）：

1. **算間隔用「本次答題前」的 `ease_factor`**，算完才更新 `ease_factor`。
2. **四捨五入採 half-up**（`floor(x + 0.5)`），不用 Python 內建 `round()` 的 banker's rounding
   （`round(2.5)` 會得 2，間隔會莫名少一天）。

## 批改結果 → 品質分數（對映唯一真相）

exam-tutor 的批改配分是申論 0–25 分、選擇 1.25／0 分，需換算為 0–5：

**申論題（依得分率）**

| 得分率 | 品質 | 25 分制 |
|--------|------|---------|
| ≥ 0.9 | 5 | 22.5 分以上 |
| ≥ 0.75 | 4 | 18.75 分以上 |
| ≥ 0.6 | 3 | 15 分以上（**及格線＝剛好及格**） |
| ≥ 0.4 | 2 | 10 分以上 |
| ≥ 0.2 | 1 | 5 分以上 |
| < 0.2 | 0 | 未達 5 分 |

**選擇題／口頭問答**

| 情形 | 品質 | `cli.py` 參數 |
|------|------|--------------|
| 答對、未經提示、答得果斷 | 5 | `--result correct` |
| 答對但自陳不確定或明說是猜的 | 4 | `--result correct --unsure` |
| 經提示後才答對 | 3 | `--result correct --hinted` |
| 答錯但方向對（近似答案、單位或數值小錯） | 2 | `--result wrong --partial` |
| 答錯 | 1 | `--result wrong` |
| 未作答／完全不會 | 0 | `--result wrong --blank` |

判定時**寧可給低不給高**：申論只寫結論未寫推導者依批改規範本來就拿不到高分，
品質分數自然跟著低，這是預期行為（間隔重複的分母是「記得牢不牢」，不是「有沒有印象」）。

## 表結構（`review_schedule.db`）

`PRAGMA user_version` 存 schema 版本，開啟時自動遷移（`storage.migrate`）。

**`review_items`**（每個知識點一列）

| 欄位 | 型別 | 說明 |
|------|------|------|
| `item_id` | TEXT PK | 見「`item_id` 命名」 |
| `title` | TEXT | 人看的名稱（如「CO₂ 藥劑保持時間計算」） |
| `category` | TEXT | 科目或系統 |
| `citation` | TEXT | 法規依據（條／項／款／目） |
| `ease_factor` | REAL | 記憶強度係數，初始 2.5、下限 1.3 |
| `interval_days` | INTEGER | 目前間隔天數 |
| `repetitions` | INTEGER | 連續答對次數 |
| `last_reviewed` | TEXT | 上次複習日（ISO；未複習為 NULL） |
| `next_review` | TEXT | 下次複習日（ISO；NULL＝未排程，視為到期） |
| `created`／`updated` | TEXT | 建立與更新日 |

**`review_history`**（每次作答一列，`item_id` 外鍵、隨項目刪除而刪）

| 欄位 | 說明 |
|------|------|
| `date` | 作答日（ISO） |
| `result` | `correct`（quality ≥ 3）／`wrong` |
| `quality` | 0–5 |
| `interval_days`／`ease_factor` | 該次算完後的值（可回溯間隔怎麼長出來的） |
| `q_id` | 對應 `progress.json` 之 `attempts.q_id`，可回查當時題目 |
| `note` | 備註（錯在哪） |

## `cli.py` 介面

```
python3 <plugin>/skills/spaced-repetition/cli.py [--data-dir DIR|--db PATH] [--today YYYY-MM-DD] [--json] <子指令>
```

| 子指令 | 用途 |
|--------|------|
| `init` | 建立或升級排程檔（冪等） |
| `due [--limit N] [--category C] [--no-new]` | 今日（含逾期）到期項目，**依 `ease_factor` 由低到高** |
| `record <item_id> (--quality 0-5 \| --essay 18/25 \| --result correct\|wrong [旗標]) [--title/--category/--citation/--q-id/--note] [--dry-run]` | 記一次作答並更新排程 |
| `preview <item_id> --quality N` | 試算「若這樣作答，下次何時複習」，**絕不寫檔** |
| `add <item_id> [--title/--category/--citation]` | 只建描述、不排程（新項目立即列為到期） |
| `show <item_id>` / `list` / `stats` / `upcoming [--days N]` | 查單項（含歷程）／全部／統計／未來排程 |
| `reset <item_id>` / `remove <item_id>` | 打回未學狀態／移除項目 |
| `import <file.json>` | 批次加入項目（只建描述） |

`--json` 一律輸出機器可讀結構。**寫入型子指令**（`init`／`add`／`record`／`reset`／`remove`／`import`）
須依 `weakness_tracking` 判斷可不可以跑，見下節。

## 與 `weakness_tracking` 的關係

| 設定 | 排程行為 |
|------|----------|
| `auto` | 完整運作：批改後自動 `record`，`/複習排程` 讀寫 `review_schedule.db`。 |
| `notes` | **預設不建排程檔**。首次使用 `/複習排程` 時問一次：要不要建 `review_schedule.db`（只存排程日期與係數，**不存作答內容**）？同意→比照 `auto` 運作並把 `review_scheduling: "on"` 記入 `config.json`；不同意→記 `"off"`，改用唯讀試算（`preview`）＋在該次複習筆記中列出建議複習日，不再重複詢問。 |
| `none` | **完全不寫檔**、不詢問。`/複習排程` 說明「間隔重複需要排程檔才能跨對話記住時機」，並改以 `/弱點複習` 或使用者口述弱點進行；需要時可用 `preview` 當場算出「答對的話下次何時複習」供使用者自行記錄。 |

`review_scheduling`（`"on"`／`"off"`）只存在 `config.json`，僅在 `notes` 模式下有意義
（`auto` 恆為 on、`none` 恆為 off，不需存）。

## 優雅退場

| 狀況 | 處置 |
|------|------|
| 無 `python3` | 說明 `/複習排程` 需要 python3（標準函式庫即可，含 `sqlite3`），本次改以 `/弱點複習` 依 `weak_tally` 選題，並說明差異。**不得由模型心算間隔**——算錯的排程比沒有排程更糟。 |
| 排程檔不存在 | 先跑 `init`；`due` 會明確回報「找不到排程檔」，不自行在打錯的路徑建檔。 |
| 排程檔 schema 版本比程式新 | `storage.migrate` 拒絕寫入並提示更新 plugin，不以舊版覆寫。 |
| 排程是空的 | 說明「先做幾輪 `/抽考` 或 `/弱點複習`，批改後會自動建立項目」，不要假裝有東西可複習。 |
| `record` 失敗（權限、磁碟） | 照常完成講解，明白告知這一題的排程沒記到、可稍後補記，不靜默略過。 |
