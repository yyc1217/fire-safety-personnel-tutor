# 使用者設定與進度檔共用規格（user-config-spec）

> 本文件為 exam-tutor、exam-trend-forecast、statute-memorizer、study-planner 共用的**單一規格來源**。
> 各 SKILL.md 只引用本文件，不各自重複定義，避免規格漂移。

## 鐵則

1. **寫入邊界**：一切使用者資料只寫在 `data_dir` 之下；`${CLAUDE_PLUGIN_ROOT}`（plugin 目錄，含 `corpus/`、`statutes/`、`reference/`）一律**唯讀**。
2. **初次詢問並記住**：設定問過一次就記住，之後不再重複詢問；使用者可隨時以 `/fs-setup` 重跑。
3. `weakness_tracking = "none"` 時完全不寫任何檔案，且不再重複詢問是否記錄。
4. **逐題落地，不累到輪末**（`auto` 模式）：**出題後立刻寫斷點、每題批改完立刻寫成績**。對話隨時可能中斷（關掉視窗、`/clear`、脈絡壓縮、雲端 session 之容器回收），累積到「一輪結束」才寫等於整輪歸零。詳見「寫入時機與併發」。
5. **斷點不得含答案（寫入端）**：`pending`（見下文）只存**題目與內部指標**，**嚴禁**寫入正解、評分要點、法源提示或任何指向答案方向的說明——否則使用者翻開檔案就等於看到答案，牴觸 exam-tutor 之「先問、後等、再解」最高原則。
6. **續作不得洩題（顯示端）**：續作提示**只能顯示**〈設備〉、模式、「本輪已完成 M／N 題」與 `items[].question_text` 原文。`articles`、`q_id`、`source`、`variant`、`max`（配分）、`asked_at` 皆為**內部指標，一律不得顯示**，也不得改寫成「涉及設置標準第 N 條」「這題 25 分的申論」這類等價說法——申論題只要知道考哪一條就等於先給了答題骨架，與鐵則五是同一條原則的兩端（一端管存、一端管顯示）。

   **管到整則訊息，不只那個提示區塊**：只要 `pending` 裡還有未批改的題，**同一則回覆的任何段落**都不得點到
   那些題的 `articles` 條號——包含「建議接下來練哪裡」「你的弱點統計」「覆蓋率還缺什麼」這類由
   `weak_tally`／`coverage` 生出來的推薦語。實測就是這樣破的：斷點區塊寫得乾乾淨淨，下一段卻建議
   「`設置標準第73條`（局部放射防護面積、放射量）還掛著錯誤紀錄」，而那正是未作答那題的考點。
   **未批改期間，弱點與覆蓋建議一律只講到〈設備〉層級**，要談條號請等該輪批改完。

   **也管沒在出題的 skill**：本鐵則的判準是「當下 `progress.json` 的 `pending` 有沒有未批改題」，**不是**
   「這次是不是出題流程」。study-planner 的進度報告與「需加強／接下來讀什麼」、statute-memorizer 的整理與
   對照表、exam-trend-forecast 的猜題報告，**同樣受本鐵則拘束**——這些 skill 的條號多半是照自己的規範讀
   `coverage`／`weak_tally` 帶出來的，各自看都合規，合起來卻正好把未批改題的考點講完。實測破口即在此：
   讀書計畫的進度報告寫了「室內消防栓（§15、§32–§38、§209）的設置標準都出過題了」，而那正是三題未批改
   題的全部 `articles`。**凡要在回覆中列條號，先確認 `pending` 為空**（`weakness_tracking ≠ auto` 或無
   `progress.json` 時視同為空）。

## 設定解析順序（所有 skill 一律照此，不得自行變體）

`level`、`weakness_tracking`、`data_dir` 三項同時存在**兩個來源**：Claude Code 的 plugin 設定
（`plugin.json` 之 `userConfig`，使用者於 `/plugin` 設定對話框填寫）與本 plugin 自己的
`config.json`。取值一律依下列順序，**取到即停、不再往下**：

| 順序 | 來源 | 取法 |
|------|------|------|
| 1 | **plugin 設定**（`plugin.json` 之 `userConfig`） | 值由 Claude Code **只在「被叫用的那份 SKILL.md」內文**代入，該檔末尾的「目前的 plugin 設定值」節即代入後的實際值——**直接看叫用中的那份 SKILL.md，非空即採用，不再讀 config.json、不再詢問**。 |
| 2 | **`<data_dir>/config.json`** | 既有使用者（v0.10.0 以前建檔者）的設定都在這裡，須完整支援，**不得因改用 userConfig 而忽略**。 |
| 3 | **初次詢問流程**（見下文） | 前兩者皆無值時才跑；問完寫入 `config.json`，並告知使用者「日後也可在 `/plugin` 的設定對話框修改」。 |

補充規則：

- **代入只發生在「被叫用的 SKILL.md」**：`${user_config.*}` 只在 skill／agent **被叫用時**代入其內容。本檔、`skills/exam-tutor/modes/*.md` 與其餘 `reference/` 檔案都是由 Read 工具讀入的**一般檔案**，寫在裡面的佔位符**不會被代入**，讀到字面未展開的 `${user_config.*}` 佔位符**不等於「使用者未設定」**，不可據以進入初次詢問流程。因此順序 1 的實際值一律回到叫用中的那份 SKILL.md 去看，本檔只定義規則。
- **凡是會用到這三項設定的 user-invocable 指令，其 SKILL.md 都必須自帶「目前的 plugin 設定值」代入區塊**（`skills/fs-quiz`、`fs-mastery`、`fs-weak`、`fs-essay`、`fs-mock`、`fs-forecast`、`fs-cram`、`fs-plan`、`fs-setup` 已具備）。指令檔本身必定是被叫用的，代入必成立；只靠指令正文「請去讀某個 skill／模式檔」是取不到值的。**`/fs-mock` 尤其不可省**——它以 `context: fork` 執行，既看不到主對話也無法提問，缺了這個區塊就只能落到 `config.json` 或預設等別。
  > 本條與上一條由 CI 把關（`scripts/ci_check_repo.py` 之 `plugin-paths` 檢查）：正文提及 `user-config-spec.md`／`<data_dir>`／`config.json`／`progress.json` 的 `SKILL.md` 若缺代入區塊會 FAIL；`SKILL.md` 以外的檔案（模式檔等）出現 `${user_config.*}` 亦會 FAIL。
- `data_dir` 因設有預設值（`~/.fire-safety-tutor`），**一律有值**，故不列入初次詢問；使用者要改就改 plugin 設定或 `config.json`。
- **只有這三項走 userConfig。** `exam_date`、`weekly_hours`、`progress_reminder`、`created`／`updated`
  仍只存在 `config.json`——`exam_date` 需要「推算下一個六月第一個週六再請使用者確認」這種互動，
  設定對話框做不到；其餘兩項本來就不主動詢問。
- **兩邊都有值且不一致時，以 plugin 設定為準**（順序 1 勝出），並在該次回應中一句話告知使用者
  兩處設定不同、目前採用哪一個，讓使用者自行決定要不要清掉其中一處。不得靜默忽略其一。

## 目錄結構

```
~/.fire-safety-tutor/           ← 預設 data_dir（使用者可改）
├── config.json                 ← 使用者設定
├── progress.json               ← 派生狀態：弱點、覆蓋度、未批改斷點（weakness_tracking = "auto" 才建立）
├── attempts.jsonl              ← 作答明細，一題一行、只 append 不重寫（同上，auto 才建立）
├── notes/                      ← 複習筆記庫（記憶重點、對照表、弱點筆記等，使用者選擇存檔時）
├── exams/                      ← 模擬試卷（整卷模擬考，使用者選擇存檔時）
├── plans/                      ← 讀書計畫（study-planner）
└── forecasts/                  ← 猜題產物（趨勢報告、懶人包、申論擬答）
```

## config.json

```json
{
  "level": "師",
  "weakness_tracking": "auto",
  "data_dir": "~/.fire-safety-tutor",
  "created": "2026-07-06",
  "updated": "2026-07-06"
}
```

| 欄位 | 值 | 影響 |
|------|----|------|
| `level` | `"師"`／`"士"` | 師：6 科（火災學、消防法規、警報、避難、水、化學系統）；其中火災學與四系統為**全申論**、**消防法規為申論 2 題＋測驗 40 題混合**。士：4 科（火災學概要、法規概要、警報與避難概要、水與化學概要），**皆為申論 2 題＋測驗 40 題混合**。影響 exam-tutor 出題科目與題型比重、exam-trend-forecast 猜題科目範圍與測驗高頻數字配置。（勿誤植「師六科全申論」。） |
| `weakness_tracking` | `"auto"`／`"notes"`／`"none"` | `auto`：每題批改後自動寫入 `attempts.jsonl` 與 `progress.json`（並在出題時留下 `pending` 斷點，支援跨對話續作），弱點複習時自動讀取。`notes`：不寫 progress.json，每次練習結束產出一份錯題與弱點筆記，問使用者「存入 `notes/` 或看完即可」（記住偏好）。`none`：完全不記錄、不寫檔、不再詢問。 |
| `data_dir` | 路徑 | 所有使用者資料的根目錄；`~` 展開為使用者家目錄。 |
| `exam_date` | `YYYY-MM-DD`（西元 ISO） | 目標考試日期。**儲存時一律轉為西元 ISO 格式**；使用者以民國格式輸入（如 `116-06-05`）時先換算再記入，避免紀年歧義。**初次使用 study-planner 時必先確認**：無此值時主動推算預設——消防設備人員考試**原則上於每年六月的第一個週末舉行（週六、週日兩天）**，取「下一個六月的第一個週六」供使用者確認或改為考選部公告日期；確認後記入，不再重複詢問。 |
| `weekly_hours` | 選填，數字 | 每週可用讀書時數。**不主動詢問**——進度以「各設備單元規定是否逐步掌握」衡量，不以時數為主；使用者主動提供時記入，僅供排程參考。 |
| `progress_reminder` | 選填，`"auto"`（預設）／`"off"` | 讀書進度有趕不上跡象時是否主動提醒（study-planner）：`auto` 主動提醒並提議重排；`off` 僅在使用者詢問進度時說明。使用者表明偏好時記入。 |

## progress.json（weakness_tracking = "auto"）

**progress.json 只存派生狀態**（弱點、覆蓋度、抽題去重、未批改斷點），逐題作答明細改存 `attempts.jsonl`
（見下節）——**派生狀態全部可由 `attempts.jsonl` 重建**，progress.json 壞了不會失去作答歷史。
載入時只讀 progress.json；需要作答明細（如「上週練了幾題」）才另外取 `attempts.jsonl` 的**尾端 N 行**，
**不得整檔載入**（作答明細會逐年累積，比照 `tags_index.json` 之「只取所需、勿整檔載入」鐵則）。

```json
{
  "schema_version": 3,
  "asked_ids": ["師/113/0806#3"],
  "weak_tally": {"by_equipment:滅火器": 2, "by_article:設置標準第31條": 1},
  "coverage": {
    "滅火器": {"asked": ["設置標準14", "設置標準31", "設置標準223"], "done": ["設置標準14", "設置標準31"], "next": "設置標準224"},
    "by_article:設置標準第14條": {"points": ["甲類場所", "…（其餘 7 個要點名）"], "done": ["甲類場所"], "total": 8},
    "by_topic:燃燒理論": {"done": ["火三角與火四面體", "燃燒型態", "完全與不完全燃燒", "燃燒速率"]}
  },
  "pending": {
    "created_at": "2026-07-29T21:04:12+08:00",
    "session_id": "78ca8a57-7203-5174-8f23-e500e5ec38f7",
    "mode": "連續出題",
    "level": "師",
    "subject": "水系統",
    "equipment": "自動撒水設備",
    "round": {"index": 2, "planned": 4, "scored": [{"q_id": "師/113/0805#Q12", "score": 1.25, "max": 1.25}]},
    "items": [
      {"q_id": "師/110/0805#甲1", "source": "corpus", "variant": "原題不變更", "type": "申論", "max": 25,
       "articles": ["設置標準第43條", "設置標準第46條"], "asked_at": "2026-07-29T21:04:12+08:00",
       "question_text": "……呈現給使用者的題目全文（不含任何答案或提示）……"}
    ]
  },
  "updated": "2026-07-29"
}
```

- `weak_tally` 與 `weak_topics` 的 key **對齊 `corpus/tags_index.json` 的維度**（`by_equipment:<設備>`、`by_article:<法規條號>`、`by_system:<系統>`），弱點複習時可直接用 jq 對 `tags_index.json` 取單鍵反查題目。
- `q_id` 格式：
  - **取自 corpus 者**沿用 corpus 題目參照 `等別/年/科目代號#題號`（如 `師/113/0806#3`）。
  - **自行命題者**（exam-tutor 依 corpus 題型風格＋本地 `statutes/` 就地命題，見 `skills/exam-tutor/SKILL.md` 鐵則二）用 `自出題/<YYYY-MM-DD>#<當日序號>`（如 `自出題/2026-07-17#1`）。
  - **整卷模擬考**（`/fs-mock` 或「出一份模擬考」之產出，批改時才產生紀錄）用 `模擬考/<YYYY-MM-DD>#<題號>`
    （如 `模擬考/2026-08-03#7`，題號沿用卷面題號）；同日出兩卷時加科目後綴（`模擬考/2026-08-03-水系統#7`）。**當日序號＝當日已用最大序號 ＋1**（同時看 `attempts.jsonl` 當日各行與現有 `pending.items`，取兩者最大值），**一經寫入即固定，後續改寫 `progress.json` 時不得重編**——同一題在 `pending` 與 `attempts.jsonl` 中換了號，就等於變成兩題，去重與弱點統計都會對不回來。
    **序號後一律再加 4 碼小寫英數隨機字尾**（格式 `自出題/<YYYY-MM-DD>#<序號>-<4碼>`，如 `自出題/2026-07-17#1-a7f3`）：
    「當日最大值 ＋1」在兩個視窗同時出題時會**各自算出同一個號**——實測兩個併發對話就同時產生了
    `自出題/2026-07-31#1`，變成兩道不同的題共用一個 `q_id`，是上一句那個毛病的鏡像（一題兩號 ↔ 兩題一號），
    弱點回顧會抓錯題目。隨機字尾不需要任何跨視窗協調就能避開；比對 `q_id` 時一律比整串，不得只比序號。
  - **`asked_ids` 只收 corpus 題目參照**（語意為「已抽用之 corpus 題目，避免重複抽題」）；自行命題之 `q_id` **不寫入 `asked_ids`**（它不佔用 corpus 抽題池）。`attempts.jsonl` 與 `pending` 等處仍照常記錄自出題之 `q_id`。
  - **`asked_ids` 於出題時即寫入**（不等批改）：語意是「已抽用」，中斷後重開才不會又抽到同一題。
- **`coverage`＝內容覆蓋度紀錄（掌握度的資料核心）**：記錄使用者對各**設備／法條／火災學主題**之「相關內容」已展現掌握的部分，供 `/fs-mastery` 計算覆蓋度，並供「還有哪些沒讀到」與主動提議下一個單元使用。**分子（`done`）與分母（`total`）皆於 exam-tutor 批改時算好存入，`/fs-mastery` 呈現時只讀相除、不重新掃描全文。**
  - **設備**（key＝**設備名**）：`asked`＝已**問過**的條文（出題進度，不論答對答錯，供連續出題接續與 study-planner 進度銜接）；`done`＝已展現**掌握**的條文（批改判定已掌握才寫入）；`next`＝建議下一個條文。**`asked` 與 `done` 語意不同，不可混寫**——`/fs-mastery` 只讀 `done`，連續出題與「還有哪些條文沒考」讀 `asked`／`next`。分母＝`reference/索引/設備條文索引.md` 該設備全部條文＋延伸知識考點（分母固定，由索引推得，可不存 `total`）。**`asked`／`done`／`next` 之條文短名格式固定為 `<法規短名><條號>`**（阿拉伯數字、無「第…條」，如 `設置標準31`；增訂條文用 `<法規短名><N>-<M>`，如 `設置標準111-1`），與同檔 `by_article:` key 一一對映：`設置標準31` ↔ `by_article:設置標準第31條`、`設置標準111-1` ↔ `by_article:設置標準第111條之1`，兩欄位可機械對齊互查。**舊版檔案遷移**：舊檔之 `done` 語意為「已問過」——讀到**無 `asked` 欄**的設備項時，將其 `done` 整批改名為 `asked`（`done` 自此由批改重新累積），並寫回。
  - **法條**（key＝`by_article:<條號短名>`）：`{"points": [該條全部要點名（依條文順序）], "done": [已掌握要點], "total": <要點總數>}`。**分母＝該條之「獨立要點數」（語意切分，非項／款數）**：一款列舉多個獨立事項時逐項計為要點——例如設置標準第 14 條第一項第一款列甲類場所、地下建築物、幼兒園等，即為多個要點，只答其一不得算整條掌握。批改時模型讀該條全文切分後，**把全部要點名稱依序存入 `points`**（含尚未掌握者——「沿用既存切分與要點名稱」必須有處可查才可實施），`total`＝`len(points)` 之衍生值（仍存，供 `/fs-mastery` 直接讀）；`done` 只收 `points` 中之字串（分子 ⊆ 分母）。未作答之條不需存任何欄，一律以 0% 呈現。**該條已有 `points` 時沿用既存切分與要點名稱、只增補 `done`，不得重切**（修法時才重切並重置該條：重寫 `points`、清空 `done`、更新 `total`）。**舊檔遷移（有 `total` 無 `points`）**：視為切分未留名——下次批改該條時重切並寫入 `points`、`total` 更新為 `len(points)`，既存 `done` 逐一對映至新要點（語意相同者改用新字串；無對應者移除——掌握度寧可低估、不虛計）。
  - **火災學主題**（key＝`by_topic:<主題>`）：`done`＝已展現掌握之**知識點**，分母＝`reference/索引/火災學主題知識點索引.md` 該主題知識點總數（分母固定，由索引推得，可不存 `total`）。
  - **key 與 `done` 命名須穩定**（跨次批改才對得上、去重才有效）：`by_article:` 條號短名**對齊 `corpus/tags_index.json` 維度**——增訂條文用「第 N 條之 M」（如 `by_article:設置標準第111條之1`，不用 `111-1`；`reference/索引/法規條文清單索引.md` 之 `N-M` 即「第 N 條之 M」）；檢修基準以章為結構單位，key＝`by_article:檢修基準第X章`（中文數字，與清單索引一致）。`done` 之知識點名稱取火災學知識點索引該條目之開頭關鍵語、法條要點沿用首次切分所定短名——同一內容點一律沿用既有字串。
  - 掌握度％＝`len(done) ÷ 內容點總數 ×100`；由 exam-tutor 批改時累積寫入（見 `skills/exam-tutor/SKILL.md`「解答與批改」與「掌握度視覺化模式」）。
  - **study-planner 只讀設備（bare-key）項**之 `asked`／`next` 銜接讀書進度；`by_article:`／`by_topic:` 前綴 key 為 `/fs-mastery` 專用，**其他 skill 迭代 coverage 時應忽略前綴 key**，勿誤當設備單元。

## attempts.jsonl（作答明細，append-only）

一題一行的 JSON（**不是** JSON 陣列，行尾不加逗號），**每題批改完立刻 append 一行**，永遠不重寫既有行：

```jsonl
{"date": "2026-07-06", "level": "師", "subject": "化學系統", "q_id": "師/113/0806#3", "score": 15, "max": 25, "weak_topics": ["by_equipment:滅火器", "by_article:設置標準第31條"], "note": ""}
{"date": "2026-07-29", "level": "師", "subject": "水系統", "q_id": "自出題/2026-07-29#1", "score": 1.25, "max": 1.25, "weak_topics": [], "note": ""}
```

欄位語意與舊 `progress.json` 之 `attempts` 陣列元素完全相同（`weak_topics` 的 key 一樣對齊 `tags_index.json` 維度）。
**選 append-only 的理由**：整檔重寫會在中斷或多視窗並行時整批損毀，append 一行則最多損失當下那一行。

## pending（未批改斷點）

`progress.json` 之 `pending` 節記錄**已問、尚未批改**的題，讓對話中斷後能在新 session 接續。
只有 `weakness_tracking = "auto"` 才寫；`notes`／`none` 不寫（此二模式**不支援跨對話續作**，使用者問起時如實說明並告知可改用 `auto`）。

| 欄位 | 語意 |
|------|------|
| `created_at` | 本斷點建立時間（ISO 8601 含時區）。用於判斷是否過期。**值一律取自系統時間**（`date -Iseconds`，已列入出題類 skill 之 `allowed-tools`），**不得由模型自行推寫**——模型只拿得到 UTC 基準的日期，自行拼出的時分秒與時區是假的，會讓 UTC+8 晚上寫下的斷點在隔天看來像「未來時間」。取不到系統時間時**只寫日期**（`YYYY-MM-DD`）並據以判斷 14 天過期，30 分鐘窗口（第 4 條）跳過。 |
| `session_id` | 建立斷點的對話。**值由叫用中的 SKILL.md 以 `$｛CLAUDE_SESSION_ID｝` 代入**（與 `user_config` 同理：本檔是 Read 讀入的一般檔案，寫在這裡不會被代入，故此處以全形括號書寫僅為說明）。取不到值時**省略此欄或寫 `null`**，不得編造——此二寫法語意相同，缺值時續作偵測第 4 條之 `session_id` 比對跳過（改以內容比對判斷），其餘照常。 |
| `mode` | `連續出題`／`快速抽考`／`弱點複習`，續作時回到同一模式。 |
| `level`／`subject`／`equipment` | 當時的等別、科目與出題主體設備。 |
| `round` | `index`＝本輪已出到第幾題、`planned`＝本輪預計題數、`scored`＝本輪**已批改**各題之 `{q_id, score, max}`（供中斷後仍算得出「輪末成績摘要」）。 |
| `items` | **已問未批改**的題（出題類型 1 可一次抽 1–4 題，故為陣列）。每題含 `q_id`、`source`（`corpus`／`自出題`）、`variant`（`原題不變更`／`類型2-改編`／`類型3-自行出題`）、`type`（`申論`／`測驗`）、`max`（配分）、`articles`（所考條號，對齊 `by_article:` 維度）、`asked_at`、`question_text`。 |

`question_text` 存**呈現給使用者的題目全文**（含選項），這樣自出題與改編題在新 session 也接得回來——
只存 `q_id` 的話，只有「corpus 原題不變更」還原得了，而本 plugin 有相當比例的題是改編或就地命題。
**依鐵則五，`question_text` 及 `pending` 任何欄位都不得寫入正解、評分要點或法源提示**；依鐵則六，`articles`／`q_id`／`source`／`variant`／`max` 是內部指標，續作時**一律不得顯示給使用者**。

**續作偵測**（各出題 skill 載入設定後、開始正題前執行）：

1. 無 `pending` → 照常開始。**不得提及斷點**——連「先前沒有未批改的斷點」這類「我查過了，沒有喔」的內部狀態播報都不要，直接進入正題。
2. 有 `pending` 且 `created_at` 在 **14 天內**、`level` 與現行設定相符 → 報告「上次在〈設備〉問到一題還沒批改（本輪已完成 M／N 題）」，並給三個選項：接續作答（把 `question_text` 原樣貼回）／丟掉重開／先看 `/fs-mastery`。
   - **續作提示之可顯示範圍（鐵則六）**：〈設備〉、模式、「M／N 題」、`question_text` 原文，**僅此四項**。不得附上條號、法源、配分、`q_id`、題型或「涉及…」之類的導言。批改後才呈現法源。
   - **整則回覆都受鐵則六管**：提示區塊之外的段落（尤其「建議接下來練哪裡」「你的弱點統計」）同樣不得點到未批改題目的 `articles` 條號，**未批改期間弱點與覆蓋建議只講到〈設備〉層級**。
   - **第三個選項改為「先丟著、做別的」**：不要主動推薦 `/fs-mastery`——它按條文列覆蓋度，等於繞道洩掉未批改題的考點。使用者自己要看，就先告知「這會列出條文覆蓋度，可能提前透露那 N 題的考點」，由他決定。
3. `created_at` 逾 14 天 → 一句話提及即可，**預設重開**，不要求使用者決定。
4. **`pending` 疑似屬於另一個視窗** → **不覆寫**，先問使用者要接手還是另開新的一輪。判準由強至弱：
   - **內容比對（主判準，一律可用）**：`pending` 之 `equipment`／`items` 不是本對話出的題（本輪根本還沒出題，檔案裡卻有別的設備／別的題目）→ 一律視為他人斷點。
   - **`session_id`（輔助）**：與現行不同且 `created_at` 在 30 分鐘內。此欄可能缺值（見上表），且同一環境的巢狀 session 可能共用同一 id，**不可當唯一判準**。
   - **時間窗口（輔助）**：`created_at` 取不到系統時間時只有日期，30 分鐘窗口無從判斷，直接跳過，改用內容比對。
5. `pending.level` 與現行 `level` 不符（中途改考等別）→ 提示不一致並**預設丟棄**。
6. 使用者選「重開」→ 刪 `pending`，但**保留 `asked_ids`**（否則又抽到同一題）。

## 寫入時機與併發

| 時機 | 動作 |
|------|------|
| 出題後（與呈現題目同一步） | 寫 `pending.items`＋`coverage["<設備>"].asked`；corpus 題另寫 `asked_ids` |
| 每題批改完 | `attempts.jsonl` append 一行；更新 `weak_tally`／`coverage.done`；該題從 `pending.items` 移除、成績進 `pending.round.scored` |
| 一輪結束或使用者說結束 | 刪掉整個 `pending` 節 |
| 任何一次寫 progress.json | **先重讀該檔再合併寫回**（不可拿記憶中的舊內容整檔覆蓋），降低多視窗並行時互相蓋掉的機率 |

**不得把整輪成績累積到輪末才寫**（鐵則四）。輪末只做**呈現**（成績摘要、弱點總結），資料在每題批改當下就該落地。

**每題最多兩次 `progress.json` 寫入**：上表同一時機的多個欄位**必須併成一次寫入**——出題時 `pending.items`＋`coverage.asked`＋`asked_ids` 一次寫完；批改時 `attempts.jsonl` append 一行（獨立、必寫），`weak_tally`＋`coverage.done`＋移除 `pending.items` 該題＋`round.scored` 再一次寫完。**不得為了「先寫 coverage 再寫 weak_tally」「先加 pending 再改 asked_ids」而拆成多次**——每一次寫入在真人環境就是一次權限提示，拆寫只是把提示次數乘上去，落地即時性一點也沒多。

**併發衝突只鎖 `pending`**：重讀時發現 `pending` 已被他人替換（見「續作偵測」第 4 條）時，**成績仍須照常落地**——`attempts.jsonl` 照常 append（append-only，零衝突風險）、`weak_tally`／`coverage` 照常重讀合併後寫回（累加與集合合併，重讀即可解決）；**只有 `pending` 這一節**暫不寫入並詢問使用者要接手還是另開。**不得因為斷點衝突就把整輪成績累到最後再補寫**——那正是鐵則四要消滅的行為，等於用「怕蓋到別人的斷點」換掉「中斷不掉資料」。

**寫入被拒絕時**：使用者拒絕 `Write`／`Edit` 權限提示時，**必須明講**「本題（本輪）未寫入進度檔，關掉對話就接不回來了」，並提議改用 `notes` 模式或在設定中允許寫入。**不得靜默略過**——使用者以為有在記錄、實際沒有，是最糟的結果。拒絕之後：

1. **每次寫入都照常嘗試**，不得因先前被拒就認定「這個環境不能寫」而整場停寫。使用者可能只是那一次不想存，或當下環境有變（權限規則調整、改用別的目錄）。
2. 同一輪內**連續 2 次以上被拒**，才改為一次性詢問「本輪都不要記錄嗎？」；**得到明確答覆**才停止嘗試，並照鐵則二記住這個選擇直到本輪結束。
3. 已停止嘗試的期間，**每輪結束時至少再提醒一次**「本輪 N 題都未寫入進度檔」，不得只在第一次拒絕時提過就再也不提。

## schema 版本與遷移

`progress.json` 之 `schema_version` 為**唯一的版本判準**，不再以「有沒有某個欄位」猜測檔案世代：

| 版本 | 特徵 | 遷移動作（下次寫入時就地完成，並告知使用者一句） |
|------|------|--------------------------------------------------|
| 無 `schema_version` | v1／v2 舊檔（0.10.0 以前） | 依下列 v2 與 v3 兩段規則逐項處理，完成後寫入 `"schema_version": 3` |
| v2 → v3 | `attempts` 仍是 progress.json 內的陣列 | 把整個 `attempts` 陣列**逐筆轉成一行**寫入 `attempts.jsonl`（順序不變），再從 progress.json 移除該欄位；`asked_ids`／`weak_tally`／`coverage` 原地保留 |
| v1 → v2 | `coverage` 設備項只有 `done` 沒有 `asked`；或 `by_article:` 項有 `total` 無 `points` | 依上文 `coverage` 各段之「舊版檔案遷移」規則處理（`done`→`asked`、下次批改該條時重切 `points`） |

遷移一律**只增不刪**：轉檔失敗或格式無法解析時保留原檔、如實告知使用者，不得逕行清空重建。

**`progress.json` 解析失敗（損毀）時的處置**，三步缺一不可：

1. **先另存原檔**：把損毀的檔案複製一份為 `progress.json.corrupt-<YYYY-MM-DD>`（同日再壞就加序號 `-2`），**才可以動原路徑**。就地覆寫等於把「壞掉的證據」一併蓋掉——這次只少一個右括號還修得回來，若是寫到一半被砍、後半段真的沒了，使用者連手動搶救的機會都沒有。
2. **重建**：能從損毀檔讀出的內容優先沿用（比從 `attempts.jsonl` 粗略重算保留更多派生狀態）；讀不出來才由 `attempts.jsonl` 重算 `weak_tally`／`coverage`；兩者皆不可讀時以無紀錄狀態繼續上課。
3. **一定要當場告訴使用者**：進度檔曾解析失敗、原檔已另存為哪個檔名、重建後保留了什麼（如「弱點 5 項與覆蓋度都救回來了」）。**全程不提＝不通過**——這與「拒絕寫入不得靜默」是同一類問題：使用者不會知道自己的進度檔出過事。

## 弱點筆記格式（weakness_tracking = "notes"）

`notes` 模式下 exam-tutor 產出的弱點筆記，**日後會由使用者提供回來供弱點複習選題**，格式須固定才能對回標籤索引（每考點以**隱藏 HTML 註解** `<!-- tags: ... -->` 存內部 tag——這些代碼給 AI 讀回用、不以可見文字輸出；`題目參照：` 行沿用 `q_id` 格式）。**版面、規則與範例見 `reference/輸出格式/弱點筆記格式.md`**（格式唯一真相）；存 `notes/<YYYY-MM-DD>_<主題>弱點筆記.md`（命名見下節）。

**`notes` 模式的跨對話接續——自己去讀，不要叫使用者手動回貼。** 任何 skill 需要弱點資料時
（弱點複習、掌握度、懶人包、讀書計畫之「需加強」），在 `weakness_tracking = "notes"` 下一律照此順序：

1. **`Glob <data_dir>/notes/*弱點筆記.md`**（此模式不寫 `progress.json`，但 `notes/` 是使用者自己同意存下的，
   讀它不違反本模式「不寫檔」的約定——**不寫 ≠ 不讀**）。
2. 依檔名日期由新到舊取**最近 5 份**（或全部，若少於 5 份）Read 回來，以各考點的隱藏
   `<!-- tags: ... -->` 註解對回 `tags_index.json` 維度；**同一 tag 在各份筆記中出現的次數即等同 `weak_tally` 的次數**，
   據以排序。註解缺漏時由考點名與條號推回。
3. **只有 `notes/` 不存在、或 Glob 不到任何檔案時，才請使用者提供筆記**——且要先講清楚「已經找過
   `<data_dir>/notes/`，沒有找到檔案」，不要在沒找過的情況下要求使用者回貼。
4. 讀到的筆記**僅供本次選題與排序**，不回寫任何檔案（`notes` 模式的約定不變）。

## 讀書計畫檔格式（`plans/讀書計畫_<等別><民國年>.md`）

study-planner 產出的計畫檔**跨對話讀回解析**（勾銷、重排、進度報告），格式須固定：檔首狀態列、單元行三段式「單元（條文）｜建議行動｜對照表」、勾銷＝`[x]`＋行尾 `✅YYYY-MM-DD`（重排保留已勾銷行）、啟動時進度報告固定三行。**版面、規則與範例見 `reference/輸出格式/讀書計畫格式.md`**（格式唯一真相）。

## 初次詢問流程

任一 skill 需要等別或記錄模式時，先跑上文「設定解析順序」；**順序 1（plugin 設定）與順序 2（config.json）都取不到值時，才進入本流程**：

1. 一次問完兩題再開始正題（缺哪項問哪項，兩項都缺就一次問完，不要分兩輪）：
   - (a) 應考等別：消防設備師（6 科；5 科全申論＋消防法規混合）或消防設備士（4 科皆申論＋測驗混合）？
   - (b) 弱點記錄模式：自動記錄到本機進度檔／每次產出複習筆記由你自行保存／不記錄？（說明三者差異）
2. 徵得同意後建立 `data_dir` 目錄與 `config.json`（`data_dir` 取自解析順序，已有預設值不必問）。
3. 寫入後**一句話告知使用者**：這些設定日後可用 `/fs-setup` 修改，也可在 Claude Code 的 `/plugin` 設定對話框直接改（後者優先）。
4. 使用者要求改設定、或執行 `/fs-setup` → 重跑本流程並更新 `updated` 日期。

**不得重複詢問**：只要解析順序取得到值就直接開始正題。使用者已在 `/plugin` 設定對話框填過等別，卻又被問一次等別，是本規格明確禁止的行為。

## 檔案命名慣例（各 skill 輸出）

| 產物 | 路徑 | 命名 |
|------|------|------|
| 趨勢報告（猜題範圍） | `forecasts/` | `趨勢報告_<等別><民國年>_<YYYY-MM-DD>.md`（exam-trend-forecast） |
| 考前必背懶人包 | `forecasts/` | `考前必背懶人包_<等別><民國年>.md`（statute-memorizer） |
| 申論猜題擬答 | `forecasts/` | `申論猜題擬答_<等別><民國年>_<科目>.md`（exam-tutor） |
| 模擬試卷 | `exams/` | `模擬考_<等別><民國年>_<科目>_<YYYY-MM-DD>.md`（整卷模擬考，含卷末答案；批改紀錄照常進 `attempts.jsonl`／`progress.json`） |
| 複習／弱點筆記 | `notes/` | `<YYYY-MM-DD>_<主題>.md`（如 `2026-07-06_水系統弱點筆記.md`）；弱點筆記內容依上節「弱點筆記格式」 |
| 讀書計畫 | `plans/` | `讀書計畫_<等別><民國年>.md`（同年同等別續用同一檔，支援勾銷與重排） |

原則：**等別＋民國年**入檔名者為同年續用之工作檔（可勾銷、可增補）；**日期**入檔名者為快照型產物。

**`<民國年>` 一律＝目標考試年度（下一次考試年）**，各 skill 計算方式須一致，避免同一批產物落在不同年份：有 `exam_date` 時取其民國年；無 `exam_date` 時比照 study-planner 之推算——取「下一個六月第一個週六」所在年（今日已過當年六月考期則為次年）。**不得以「今年」（當前系統年）充當考試年**。
