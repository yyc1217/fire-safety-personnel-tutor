# statutes 法條索引

本目錄存放**命題大綱所涉法規的現行全文 md**，由使用者手動自官方來源下載、整理後放入。skill 對本目錄**唯讀**。

**一部法規一個資料夾**，資料夾名＝該法規 md 檔名（去 `.md`）：

```
statutes/<編號_法規名>/
├── <編號_法規名>.md   ← 轉錄條文
├── 圖1.png …          ← 附表與附圖
└── 原始檔案/          ← 官方原始檔（PDF／DOC／ODT）
```

取條文時路徑恆為 `statutes/<編號_法規名>/<編號_法規名>.md`。

清單依考選部現行命題大綱整理：

- 消防設備師（六科）：113.10.11 選專五字第1133301396號公告修正版
- 消防設備士（四科）：113.4.22 選專五字第1130001208號公告修正版（消防法規概要）

> 「適用」欄：**師士**＝師、士命題大綱皆列；**師**＝僅消防設備師命題大綱列（士不考）。士為「概要」，法規範圍為師之子集。

## ⚠️ 法規時效（務必遵守）

法規會修正，本目錄的 md 是「整理當下的版本快照」。為避免引用過期條文：

1. **每份 md 檔首必須標注版本日期**（該法規最後修正日期，見下方格式）。
2. **skill 於每次引用法條時，須先核對是否為最新修正版**，比對來源固定為兩個官方系統：
   - **全國法規資料庫**：<https://law.moj.gov.tw/>（法律、法規命令）
   - **內政部消防署「消防法令」**：<https://www.nfa.gov.tw/>（各類認可基準、檢修基準、作業基準等行政規則多由消防署發布，部分未登載於全國法規資料庫；若深層連結變動，以 web 搜尋「內政部消防署 法令規章」定位現行頁面）
   - 消防署站點憑證鏈不完整、程式化抓取常失敗；不可達時改查**內政部主管法規共用系統** <https://glrs.moi.gov.tw/> 或**行政院公報資訊網** <https://gazette.nat.gov.tw/>。各檔追蹤來源與核對紀錄見 `docs/法規版本追蹤.md`（`scripts/check_statute_versions.py` 可機械比對）。
3. 若官方現行版本之修正日期 **晚於** md 檔首標注日期 → 以官方現行版為準作答，並向使用者提示「本地 md 已過期，建議更新」；同時於該檔檔首加「🔴 已知過期」警示、寫入 `docs/法規版本追蹤.md`（格式見 `statutes/2_03` 檔首）。官方現行版取不到時，引用須顯著標注「快照版本 X、官方已於 Y 修正」，不得靜默沿用。
4. **建議更新頻率**：使用者至少**每季**、或**每次報名考試後**，重新下載核對一次本目錄全部 md；重大修法（如消防法、設置標準）公告後應立即更新。

## ⚠️ 大檔取用（務必遵守）

**取條文一律「先定位條號行號，再 Read 帶 offset／limit 只讀該區段」，不要整檔 Read。** 法規 md 動輒數萬字，整檔載入會讓每輪多讀大量用不到的條文。

```
Grep  pattern: ^## 第 17[5-9] 條
      path:    statutes/2_01_各類場所消防安全設備設置標準.md
      output_mode: content   -n: true
→ Read 該檔 offset=<起始行> limit=<區段行數>
```

> **定位用原生 `Grep` 工具或 shell 的 `grep` 都可以，「不要整檔 Read」才是規範。** 能選就選原生工具：
> 它不需額外授權、也不受 Bash 的工作目錄限制；經由 Bash 執行的指令每次都要使用者點同意，
> 被拒時整條路會斷——屆時改用原生 `Grep`／`Read`，**不可因此放棄本目錄改為憑記憶作答**。

**`2_01_各類場所消防安全設備設置標準/` 特別注意**：該檔 **4,239 行，超過 Read 工具預設 2,000 行上限**。整檔 Read 會被**靜默截斷**——只拿到前半部，且不會有任何錯誤提示。後果是查後半部條文（§175 緊急照明、§180 以後之公共危險物品專章等）時誤判「查無此條」，或引用到不完整的條文。取該檔條文**必須**走上述「定位行號 → Read 帶 offset」流程。

本目錄其餘 md 均在 2,000 行上限內，整檔 Read 不會截斷，但仍以精準取用為原則。

## 附表／附圖處理原則

法規附表、圖例存於該法規資料夾之 `原始檔案/` 子資料夾，並於該法規 md 末「附表／附圖（附件）」節處理：

1. **可乾淨轉換的資料表** → 內嵌 markdown 表格（如檢修頻率表、保留空地寬度表）。
2. **過於複雜無法乾淨轉換的表**（跨欄跨列合併，如公共危險物品種類分級管制量表）→ **拆解成 skill 可解析的結構**（分類 → 種類 → 分級／管制量 等巢狀區塊）內嵌，無法確認之儲存格標「（見原檔）」，並**附原始檔連結**供權威查證。
3. **圖例、標示樣式、空白表單** → 僅附檔案連結（`[名稱](原始檔案/<檔名>)`）。
4. 含半形括號 `()` 之附件檔名一律改全形 `（）`，避免破壞 markdown 連結。

> **例外（識圖出題資源）**：「消防機關辦理建築物消防安全設備審查及查驗作業基準」附件三之消防圖說圖例，雖屬圖例類，因係識圖考題來源，已逐格轉換：圖例符號裁切為圖檔（`2_02_消防機關辦理建築物消防安全設備審查及查驗作業基準/原始檔案/附件三_圖例/`），並附[對照表 md](2_02_消防機關辦理建築物消防安全設備審查及查驗作業基準/原始檔案/附件三：消防圖說圖示範例.md) 與 JSON 索引（`附件三_圖例_index.json`），供出題 agent 直接取用；重新產生用 `scripts/extract_legend_symbols.py`。
